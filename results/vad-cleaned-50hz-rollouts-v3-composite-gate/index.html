三部分门与按动作分配执行器：VAD_Cleaned_50Hz_Rollouts_V3 构建

Date/scale: 2026-07-26 / 1392 候选 clip · 8 动作 · 两个执行器 · 人工标注 42 条 + 抽检浏览 137 条 Output profile: markdown-project-report（HTML 同目录） Results profile: dataset-verifier Verdict: PASS

V2 的已知缺口是"平滑度未门控"，其实质是 locomotion：D6 在 walk/kick 上 jerk 达参考的 6.8/4.4 倍。本报告说明 V3 如何用一道三部分门 + 按动作分配执行器把这个缺口补上，以及过程中发现的一条与 reward 设计相关的数据规律。

1. Conclusion

PASS。

  • Decisive evidence: V3 接受 1063/1392（76.4%）、10111 秒；walk 由 SONIC 执行后过门率 92%（D6 仅 0.5%），其余六个动作沿用 D6 且过门率 70–87%（§4）。
  • Counter-signal: kick 仅 227 秒（占 V3 时长 2.2%）、crouch 461 秒（4.6%），而三个上肢动作占 65%——动作时长分布明显偏斜；kick/walk 由 SONIC 执行，其手臂相位晚 80–100 ms，本门对这两个动作只卡腿，故未拦截。
  • Not shown: 端到端 planner 训练验证（本数据集尚未证明能改善下游指标）；六个上肢动作的门未经人工校准（阈值由 walk/kick 的标注外推）；kick 的自动判据（现有 40 个指标全部无效，见 §5）。
  • Decision: V3 交付下游 planner 训练使用；MoE tracker 续训的两个方向见 §5 Next。

2. Problem and terminology

本报告回答：在"不抖动、物理可执行"的前提下，如何从 rollout 采出可用于 Latent Diffusion Planner 训练的 50Hz 执行态数据，以及每个动作该由哪个执行器产出。

出发点是两个执行器互补且都已实测到的失败模式：

  • D6 的失败在 locomotion：六个上肢/蹲起动作 jerk 比 0.84–1.16、相位延迟 0 ms（可用）；但 walk/kick 上 jerk 比 6.77 / 4.40，且执行态运动量达参考的 2.7× / 1.9×——多出的运动在参考里不存在，是它自生的抖动。
  • SONIC 的失败在两种"高分陷阱"：locomotion 忠实（jerk 比 1.14 / 1.45、运动量保留 1.01 / 1.03、腿部延迟 20–40 ms），但它会把动作低通抹平（crouch 运动量只剩参考的 0.85，即蹲浅了 15%）、并且上肢系统性晚 80–100 ms（用延迟买平滑）。

由此得到两个设计决定，构成本报告的 Method：

  • 按动作分配执行器：kick·walk → SONIC（取其 locomotion），其余六个 → D6（取其上肢与零延迟）；
  • 门必须三部分：只卡抖动的单边门会被上述两个陷阱刷分——低通抹平能把 jerk 比刷得比参考还低，延迟不改变任何整段统计量。所以在抖动上界之外，加运动量双边区间（式 3，堵抹平与虚增）和相位延迟上界（式 4，堵延迟换平滑）。各式的精确定义见 §3.1。

3. Method

3.1 Gate definition

记 q_exec, q_ref ∈ R^{T×29} 为同一 clip 的执行态与参考关节角序列（50 Hz，取公共前缀 T 帧），f = 50。逐关节有限差分：

v = Δq · f        （关节速度）        a = Δv · f        （加速度）        j = Δa · f        （jerk）
RMS(x) = sqrt( mean(x²) )，对全部 29 关节 × 全部帧池化

生产门（V3 入选判据，四条同时满足）：
(1) 抖动-jerk      R_j = RMS(j_exec) / RMS(j_ref)                        R_j ≤ 1.5
(2) 抖动-accel     R_a = RMS(a_exec) / RMS(a_ref)                        R_a ≤ 1.5
(3) 运动量保留      R_v = RMS(v_exec) / RMS(v_ref)               0.85 ≤ R_v ≤ 1.15（双边）
(4) 相位延迟       τ* = argmax_{|τ| ≤ 200 ms} ρ( shift(v_exec^G, τ), v_ref^G )      |τ*| ≤ 40 ms
                  ρ = 逐关节去均值后的归一化互相关；关节组 G：动作 ∈ {walk, kick} 取腿部
                  关节 (0–11)，其余动作取手臂关节 (15–28)

入选 ⇔ (1) ∧ (2) ∧ (3) ∧ (4)

校准门（仅用于验证"数值门能否复现人工判定"，不参与 V3 筛选）：
(5) over_ref_far ≤ 3.65  ∧  amp_ratio ≥ 0.79
    over_ref_far = 远离落地 ≥120 ms 的安静帧上，腿部关节速度 8–25 Hz 频带能量 ÷ 同一
                   参考自身该频带能量（1.0 = 与参考同水平）
    amp_ratio    = 腿部 0.5–4 Hz 主运动带幅度 ÷ 参考同量（≥ 0.79 为过）

每一式各堵一条 §2 已实测的失败通道：

  • 式 (1)(2) 拦自生抖动：执行态凭空多出的高频运动（D6 在 locomotion 上的失败模式）。
  • 式 (3) 双边：下界拦低通抹平（SONIC 把 crouch 蹲浅 15%），上界拦运动量虚增（抖动的另一种表现形式）。
  • 式 (4) 拦用延迟买平滑（SONIC 上肢晚 80–100 ms）。延迟不改变任何整段统计量，式 (1)–(3) 对它全盲，必须单独设项。

抖动项用式 (1)(2) 而不用校准门的 over_ref_far，两个原因：

  • 覆盖：式 (5) 依赖足够多的"安静帧"，短 clip（<140 帧）常算不出读数——42 条标注中 2 条如此，其中 1 条只看幅度会被误判为 pass。式 (1)(2) 对任意长度 clip 可算。
  • 口径来源：阈值 1.5 是 V2 报告 §5 事前提出的门控口径，不是本次看数据拟合的。

实现位置：式 (1)–(3) 在 scripts/score_tracker_jitter_metrics.py::score_pair；式 (4) 在 scripts/build_v3_rollout_dataset.py::phase_lag_ms；式 (5) 在 scripts/probe_jitter_attribution.py。

5. Analysis

  • Finding：门必须是双边加相位的。 单边平滑门可被两种方式刷高：把参考低通掉（SONIC 在 crouch 上抹 15%，§4.2），或用延迟换平滑（SONIC 上肢 80–100 ms）。补上运动量双边区间与相位项后，两种刷分都被拦下，且 walk 的分配结论不变（SONIC 仍 97%）。
  • Finding：kick 的可接受性现有指标全测不到，但时序指标测得到。 42 条人工标注中，walk 侧一道两参数门可 100% 复现判定（18/18）；kick 侧扫遍 40 个整段平均指标最佳 87%，而标签打乱后同一扫描中位数也是 87%（p=0.825），即全属多重比较假象。改用按"动力链与起停果断性"预设的 7 个时序指标后，减速段过冲达 91.3%、置换检验 p=0.015。
  • Working interpretation（user 已确认）：差距在时序局部，而奖励与评测都是整段平均。 人工判 fail 的 kick 减速时过冲 0.584 rad、起手耗时是参考的 1.83 倍；判 pass 的分别是 0.351 与 0.971；SONIC 是 0.298 与 1.000。这两个窗口各只占几百毫秒，在整段平均里被稀释到不可见——现行 reward 与现行指标都看不见它们。
  • Unknown： 动力链的顺序指标（髋→膝→踝峰值排序）在所有执行器上均为 0，说明该测法无效，"动力链"这一半尚未真正测到；上述时序指标只在一条 tracker（Spec_legvel）上验证过，作为通用判据仍需换臂复测。

Next

MoE tracker 续训两个方向：

  1. 尝试蒸馏 SONIC。 上界探针已证明其输出更优（hybrid macro MPJPE 0.0343→0.0306，locomotion jerk 仅我方 0.17–0.33 倍），但 2 轮 live-teacher DAgger 未通过验收。本次发现使该失败值得重查：SONIC 的优势主要在时序结构上，而当时把它的动作映射到 action_scale=2.0（其原生约 0.41）并固定 std=0.05，这个增益错配恰好可能丢掉时序信息。
  2. 尝试复刻 locomotion 效果。 目标是让我们的 tracker 在 walk/kick 上达到 SONIC 的水平（jerk 比 1.14/1.45、运动量保留 1.01/1.03）。据 §5 的工作解释，方向不是新增一项奖励，而是给起动与减速窗口加权——同样的跟踪奖励，在这两个时序窗口上放大权重；这是改权重分布而非新造优化目标，Goodhart 风险较小。
