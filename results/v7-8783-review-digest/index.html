八类动作概览

动作审查发现
walk 质量最好。小比例动作有上肢 retarget 抖动；转身段不含周期（设计预期）
wave_arms end-effector 水平方向有周期，竖直方向分量少、识别率低。容易漏切，尤其同一个周期内。 rtgt 抖动（不是左右手抖动）。driver-hand 机制不在前端可见，待 Nolan 复核
punch 另一只手 guard 时，闲手摆动或拉手会被误记为出拳 → 漏拳。 one-strike 队列中 60% 不可用：根因是 periodic 动作漏了周期，被错误丢入 one-strike
clap periodic 全部可用。穿模、坐姿是零星问题。one-strike 废数据和切错占多数
kick periodic ↔ one-strike 互相混入是主要问题。幅度大时助跑侧腿被算入周期； 骨盆也动时 one-strike 被拆为 2 个周期。one-strike 本身极少问题
crouch hold 混入坐姿动作；retargeting 膝盖抖动、手↔腿穿模；少量带起身的 hold； 带踮脚的 crouch 脚会有点浮空。one-strike 几乎全部干净
bow hold-bow 没问题。one-strike 的唯一问题是 retarget jitter（28% 有 note）
cross_arms 切分全部正确，但 95% 有手臂穿模——retarget 质量问题，不是切分 bug

目标与定义

对 v7 八动作分割包 babel_soma_semantic_clean_v7_final 的切刀输出进行人工逐窗审查，回答：各类动作的分割质量是否达到可用标准？ failure modes 的根因是切分算法还是 retargeting 质量？

术语本报告中的定义不要混淆
单次实例 (lingfanb) v7 导出的一条 unit，审查者判“可用”。有 note = 有瑕疵，无 note = 干净 审查页上按脚/按手拆开的色块不是 unit
都不对 (neither) 两套方案（SIGNAL 和单次实例）都不可用 → 大问题 不一定全部错，可能只是本窗方案不对
SIGNAL 对照信号方案更优，单次实例还不够好 PCA 只作对照，不记投票
periodic 本窗 ≥ 2 条连续 unit（punch/clap 按条数；kick 按是否回到双脚着地） v7 字段 temporal_type 可能不一致
one-strike 本窗仅 1 条 unit（punch/clap）或踢后双脚着地空档 > 0.8 s（kick） 不等于 v7 字段 one_shot
retarget jitter MoCap→G1 retargeting 引入的高频抖动 不是动作本身的振荡
穿模 retarget 后肢体几何体互相穿透 切刀不检测穿模
晋级-only note 仅说明检测结果未被采纳的备注，不视为瑕疵（31 条被剥除） clap periodic 21 + punch periodic 10
