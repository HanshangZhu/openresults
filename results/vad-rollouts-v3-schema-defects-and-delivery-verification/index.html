V3 rollout 数据集的交付核验与跟踪质量包络

Date/scale: 2026-07-29 / 1063 clip · 10111 秒 · 8 动作 · 两个执行器 · 50 Hz Output profile: markdown-project-report Results profile: dataset-verifier Verdict: PASS

VAD_Cleaned_50Hz_Rollouts_V3 是一批 50 Hz 的执行态人形机器人轨迹：把带情感标注的参考动作交给物理控制器实际跑一遍，留下机器人真正做出来的状态，供下游 planner 训练使用。本报告回答两件事——交付出去的这批文件与它自己声明的数据契约是否一致，以及它的跟踪质量在典型与最坏情况下分别是多少。

1. Conclusion

PASS。

  • Decisive evidence: 1063/1392 候选 clip 通过三部分门（§3）；交付版通过数据集自带的契约校验，1063 条 0 失败，而同一校验器在被它取代的两个早期构建上分别报 1064 与 496 处失败（图 1 右）。
  • Decisive evidence: 把骨盆对齐后，全部八个动作的肢体偏差落在 0.033–0.128 m（主表）。这是下游若只消费相对姿态时能拿到的精度。
  • Counter-signal: 筛选门不测世界坐标位置。同一批 clip 的世界系肢体偏差跨动作相差 45 倍，walk 中位 0.116 m、最差 1.314 m。差额几乎全部是沿时间累积的根部漂移，且只出现在两个 locomotion 动作（图 2）。
  • Decision: 交付 Tracked_Cleaned_VADCompose_V3_planner50hz_rev3.tar.zst（sha256 0162201916ec4b27…）。消费相对姿态的下游可直接使用；消费世界坐标轨迹的须自行处理漂移，或按主表 p90 列设阈值筛选。

2. Problem and terminology

研究问题：这批交付出去的执行态轨迹，其字段内容是否与数据契约一致，以及它相对参考动作的位置精度在典型与最坏情况下各是多少。

5. Analysis

  • Finding：失效模式只有一种——全局漂移，且只出现在 locomotion。 世界系偏差跨动作相差 45 倍，对齐骨盆后全部落进 0.033–0.128 m（主表）。最差那条 walk 世界系 1.314 m、对齐后 0.105 m：参考走出去再折返，执行没折返到位，而步态本身跟得住（图 2 右）。上肢动作即使取最差 clip 也只到 0.096–0.181 m。把相对偏差按各动作参考自身的活动幅度归一后为 7.8%–18.7%，locomotion 落在较好的一端（walk 9.2%），即根部漂移不牵连相对动作质量（表 A2）。
  • Finding：这些 clip 是按设计入选的，不是筛漏。 三部分门全部作用于关节量，没有任何一条读世界坐标位置（§2 术语表）。因此漂移大的 locomotion clip 能过门是判据定义的结果；本报告不改动门，只把它没测的那一维单独量出来交给下游。
  • Working interpretation（待验证）：难度指标解释不了这些偏差，动作类型才能。 三个参考侧 stressor 与漂移的合并秩相关为 0.44 / 0.57 / 0.39，按动作分组后平均降到 0.19 / 0.24 / 0.16；对肢体偏差更彻底，动作内平均 0.08 / 0.07 / −0.00，且符号在动作间翻转。arousal 对肢体偏差的动作内相关正好为 0，说明它是动作类型的代理变量，不是独立难度轴（表 A2）。
  • Next：给下游一个明确口径，并把契约回读固化进流程。 消费相对姿态可直接使用；消费世界坐标轨迹须自行处理漂移或按主表 p90 列筛选。scripts/validate_v3_dataset.py 已随数据集交付，后续任何构建在打包前须先通过它——前两次构建的问题全部属于"字段存在但内容不对"，只有拿契约回读数据才看得见。
